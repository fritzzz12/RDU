# Local RDMS architecture

## Runtime boundary
React is a view over authorized server snapshots. Express owns authorization and all state transitions. SQLite persists records and immutable review/audit events; protected PDF bytes are stored outside the public build. Browser controls never confer permission. Built frontend and API are same-origin; Vite proxies API during development.

## Identity and authority
Demo identity selection creates a random HttpOnly, SameSite session cookie. Every protected request reloads the account and requires Active status, so suspension takes effect on existing sessions. This is not authentication suitable for deployment: anyone using the demo picker can choose any active identity. No confidential production records belong here. Mutating cross-origin browser requests are rejected.

Admins and Directors see university-wide records. Heads see their department; researchers see owned projects. Only Heads review, waive conditional requirements, upload for faculty or advance phases within their department. Admin/Director may archive completed work and publish announcements; only Admin manages accounts/settings. Review policy was explicitly selected by the user rather than inferred from broad administrative access.

## Evidence and transitions
Shared catalog IDs identify the exact image checkbox lines. Each requirement tracks the latest immutable document version's review state. Approved evidence cannot be silently replaced. Non-applicability applies only to conditional items and requires an audited reason. Advancement rereads authoritative current-phase requirements; only approved or justified conditional exclusions pass. Monitoring/evaluation remains cross-lifecycle history. The provisional personally funded variant deliberately reuses the supplied standard checklist and is labeled in the UI.

PDF parsing is asynchronous, so uploads reload authoritative state and session after parsing. Saving metadata is synchronous and transactional, preserving both concurrent submissions. Failed metadata saves remove new file bytes. Upload attempts from the UI retain a UUID submission key across retries; a persisted fingerprint binds that key to the bytes and signed metadata. An identical retry returns the original version without new files, notifications or audit events, even after review. Altered reuse fails. SQLite enforces key uniqueness. Intentional revisions use new keys; legacy unkeyed API uploads create versions rather than receiving implicit content deduplication. Audit and review rows reject update/delete through SQLite triggers. Files are served only after project authorization. PDF validation checks extension, size, magic, and EOF; this is not malware scanning or full PDF content validation.

## Persistence and reporting
The local prototype stores structured domain records as JSON with relational keys for ownership, documents, recipients, sessions and reviews. Schema creation is idempotent on startup. Changes to catalogs must preserve IDs already referenced by stored requirements. This is a deliberate small-prototype schema, not a claim of normalized production migrations.
Dashboards derive from scoped snapshots. All 13 report selections use one shared report derivation for preview and CSV, so aggregation, compliance, missing requirements and project activity respect the same filtered scope. CSV is server-scoped, formula-escaped and export-audited. Printable reports are generated by the browser from authorized state and their requests are logged; a browser print request is not proof the user saved a PDF. Announcement body text is rendered as text, not arbitrary HTML. The assistant summarizes scoped metadata deterministically; it never changes project or document state.

## Workspace design boundary
The user approved the Research wayfinding proposal: persistent navy navigation, cool light work surface, teal actions, phase-specific evidence paths, and familiar web controls. The signature interaction is a selectable lifecycle path revealing exact checklist evidence and advancement state. This is an Operate screen, not an institutional brand redesign. The built tokens, components and responsive rules live in DESIGN.md and .impeccable/design.json; the exploratory direction seed was seed:0b5e5749cea9fc7c. Closed small-screen navigation is inert; Escape restores trigger focus. Metadata and lifecycle numerals use contrast-checked darker secondary text. No raster illustration or official logo is shipped.

## External-service boundary
Google OAuth and email delivery are not configured and are not represented as completed integrations. Typed e-signatures are demo attestations, not certified digital signatures. Official logos/colors and the personally funded checklist require supplied source assets. Optional reviewer delegation, production retention/backup policy, malware scanning, and deployment hardening are not implicit in this local prototype. Reference directories and the enforced permission matrix are read-only; announcement content is plain text without attachments or scheduling. Additional contact data, rich-text editing, advanced notification/report filters, Excel output and live AI are not present. README.md explicitly lists remaining source-spec gaps rather than implying every proposed MOD is production-complete.
